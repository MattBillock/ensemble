# Activity Tracking Fixes - Requirements Document

## Executive Summary

This project addresses three critical bugs in the Ensemble UI agent system that prevent proper activity tracking. Files generated by agents, request counts, and activity metrics are not being correctly recorded or surfaced via the activity APIs.

## Problem Statement

The Ensemble UI shows zero files generated and zero agent counts even when agents are actively producing files and completing tasks. This is a **tracking/visibility bug**, not a functionality bug - the agents ARE working correctly, but their activity is not being reported to the UI.

### Root Causes Identified

1. **Bug #1: WriteFileTool Does Not Record to Activity Tracker** (HIGH PRIORITY)
   - Location: `src/runtime/agents/tools.py` - `WriteFileTool.execute()`
   - Impact: Files written by spawned agents are never tracked

2. **Bug #2: Request Counts Never Incremented** (MEDIUM PRIORITY)
   - Location: `src/runtime/agents/activity_tracker.py`
   - Method `increment_request_counts()` is defined but never called
   - Impact: Timeline view shows 0 agents, 0 files, 0 commits for all requests

3. **Bug #3: File Tracking Only Scans Output Directory** (LOW PRIORITY)
   - Location: `src/field/ensemble_ui/backend/main.py`
   - Only files in output directory are scanned; files elsewhere are missed
   - Impact: Test files, source files written outside output directory not tracked

## Objectives

1. **Primary**: Ensure all file writes by agents are tracked via `record_file_generated()`
2. **Secondary**: Auto-increment request counters when agents start, files generate, commits occur
3. **Tertiary**: Validate fixes by confirming `/api/activity/files` returns correct data

## Scope

### In Scope
- Modify `WriteFileTool` to accept and use tracking context (agent_id, request_id, agent_name)
- Modify `ToolRegistry.default()` to pass tracking context to WriteFileTool
- Add auto-increment calls to `record_agent_started()`, `record_file_generated()`, `record_git_commit()`
- Add tests to verify activity tracking works end-to-end
- Update existing tests if needed to accommodate new parameters

### Out of Scope
- Modifying the activity API endpoints (they already work correctly)
- Changing the frontend display logic (it already consumes the API correctly)
- Major refactoring of the tool system architecture

## Technical Requirements

### Fix 1: WriteFileTool Tracking

**Current Implementation:**
```python
class WriteFileTool:
    def __init__(self, agent_definition: Optional["AgentDefinition"] = None):
        self.agent_definition = agent_definition
```

**Required Changes:**
```python
class WriteFileTool:
    def __init__(
        self, 
        agent_definition: Optional["AgentDefinition"] = None,
        agent_id: Optional[str] = None,
        agent_name: Optional[str] = None,
        request_id: Optional[str] = None
    ):
        self.agent_definition = agent_definition
        self.agent_id = agent_id
        self.agent_name = agent_name or (agent_definition.name if agent_definition else "unknown")
        self.request_id = request_id
```

**In execute() method, after successful write:**
```python
if self.agent_id and self.request_id:
    try:
        from .runtime import AgentRuntime
        activity_tracker = AgentRuntime.get_activity_tracker()
        
        file_ext = file_path.suffix.lower()
        file_type_map = {
            ".md": "markdown", ".py": "python", ".js": "javascript",
            ".tsx": "typescript-react", ".ts": "typescript",
            ".json": "json", ".yaml": "yaml", ".yml": "yaml", ".txt": "text"
        }
        file_type = file_type_map.get(file_ext, "unknown")
        
        preview = content[:500] if len(content) > 500 else content
        
        activity_tracker.record_file_generated(
            agent_id=self.agent_id,
            agent_name=self.agent_name,
            request_id=self.request_id,
            file_path=str(file_path),
            file_size=len(content),
            file_type=file_type,
            preview=preview
        )
    except Exception as e:
        logger.warning(f"Failed to record file generation: {e}")
```

### Fix 2: ToolRegistry.default() Update

**Current Implementation:**
```python
registry.register(WriteFileTool(agent_definition))
```

**Required Change:**
```python
registry.register(WriteFileTool(
    agent_definition=agent_definition,
    agent_id=agent_id,
    agent_name=agent_definition.name if agent_definition else None,
    request_id=request_id
))
```

### Fix 3: Auto-Increment Request Counts

**In `record_agent_started()`:**
```python
def record_agent_started(self, ...):
    # ... existing code ...
    self.increment_request_counts(request_id, agents=1)
```

**In `record_file_generated()`:**
```python
def record_file_generated(self, ...):
    # ... existing code ...
    self.increment_request_counts(request_id, files=1)
```

**In `record_git_commit()`:**
```python
def record_git_commit(self, ...):
    # ... existing code ...
    self.increment_request_counts(request_id, commits=1)
```

4. Minor performance impact of tracking is acceptable

2. Must not break existing tests
3. Changes should be localized to the identified files
